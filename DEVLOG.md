## 2026-11-11 · run 14 (scheduled) · backlog #5 lap and development lengths by size and grade

**Done:** laps are no longer one project number. The AS 3600 Section 13 value is computed beside every lap the model uses, an optional lap table typed from the drawing's general notes drives the laps per bar size and case, and any lap in use that is shorter than the formula is flagged. The flat "Lap, all bars" stays the default (DECISIONS.md 2026-11-04).

- Model: `lapCalc(o)` (between the MODEL markers) is the Section 13 engine from Findings 2 (`research/02-lap-and-development-lengths.md`; secondary sources, clause numbers to be verified against the purchased standard): tension Lsy.tb = 0.5 k1 k3 fsy db / (k2 √f'c) with the 0.058 fsy k1 db floor, f'c capped at 65, k1 = 1.3 when more than 300 of concrete sits below a horizontal bar, k2 = (132 − db) / 100, k3 = 1 − 0.15 (cd − db) / db within 0.7 … 1.0, cd = min(cover to the bar, half the clear spacing s − 2db) with the governing one named (`cdGov`), lap = 1.25 × Lsy.tb (Cl 13.2.2, k7 1.25, k4 = k5 = 1; beam bars as narrow-element contact laps, sb = 0); compression Lsy.cb = 0.22 fsy db / √f'c ≥ max(0.0435 fsy db, 200), lap = max(Lsy.c, 40db, 300) (Cl 13.1.5.2 / 13.2.4). Computed laps round UP to 50 (`LAP_ROUND`); the comparison that flags a shorter lap uses the unrounded value. The floor is applied inside Lsy.tb as Findings 2.4's default table does (the Cl 13.2.2 reading is ambiguous in the secondary sources; the conservative one is used, noted in the code comment). `parseLapTable(text)` reads a B23-style table: a case header (`SLAB`, `BEAM <300`, `BEAM >300`, `BEAM` alone = both beam cases, `COLUMN` / `WALL`) with its f'c grades, then `N12 600 500 450` rows; a grade-less case (B23's columns) takes one value per size; `#` comments; every bad line is an error by line number with the reason (case first, N13 not a size, 3 laps for 2 grades, repeated header, no rows under a case, not a header or a row). `lapLookup(table, case, size, f'c)` returns the cell, "missing" when the case has grades but not this f'c (an error: add a column or change f'c), or null (no row: the flat lap, or the detail's fixed value, is used and one warning lists the gaps). `lapUse` in `buildModel` resolves each use and keeps `M.laps.rows` (one per case / size / spacing / cover / k1 / source), with `lapped` = the bar ends that actually lap with it, so trimmers and extras that never lap do not raise flags.
