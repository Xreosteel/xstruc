# X Struc — instructions for every working session

X Struc turns engineers' slab and precast drawings into 3D reinforcement models, placing drawings and bar schedules; it is growing from a prototype into a SaaS. Owner: Baji (Xreosteel). Read this file, then `DECISIONS.md` (Baji's decisions; build to them, don't re-ask), then `DEVLOG.md` (latest entry first), then `BACKLOG.md`. The architecture is the **v2 · Lean build** tab of https://claude.ai/artifact/D7Jf59XywqkZmL8UK7xeGm (read it with the Claude Docs tools, not WebFetch); `docs/architecture.md` and `docs/adr/` are the short versions in the repo.

## What exists (a pnpm + Turborepo monorepo since 2026-11-20)

- `packages/engine` — **the engine, the single source of truth**: `src/engine.js` (the former MODEL block of the prototype, moved verbatim: `DEFAULT_CFG`, `parseCallout`, `buildModel` → `{bars, runs, chairs, marks, errors, warnings, …}`, `buildPanel`, `buildSheet`, `buildSection`, catalogues), `src/index.js` (`ENGINE_VERSION`, `canonicalOutput`), `src/index.d.ts` (the typed public API). Pure and headless: no DOM, no THREE, no network, no clock, no randomness (its tests check this). Bump `ENGINE_VERSION` and `package.json` together on any change that alters an output.
- `apps/prototype` — the single-page viewer and installable app, live until `apps/web` replaces it. `index.html` is a **template**: its `// @@ENGINE …` line is replaced by the engine block (MODEL START … MODEL END) by `scripts/build.js` → `dist/index.html`, the self-contained page (three.js r128 + OrbitControls from CDN, everything else inline). It renders the example Level 1 floor (layers A–D, beams, columns with starters, set-down, step, balcony, openings, L/Z-bars, extras, stair, mesh), a fixing-order stepper, tags, inspector, live schedule, section cut, placing sheets, site mode, and the precast panel mode (NF / FF faces, bars or mesh). Viewer code lives in `index.html`; engine code only in `packages/engine`.
- `apps/prototype/app` + `scripts/build-app.js` — the installable app (backlog #34) that GitHub Pages serves: https://xreosteel.github.io/xstruc/. Keep the page free of a manifest link (the artifact has no worker); the `appShell` block does nothing without the manifest. The page keeps both modes' inputs in localStorage (`xstruc.inputs.v1`).
- `apps/web` — **the application** (Next.js 16 App Router, React 19, Tailwind 4) for Vercel: Supabase sign-in (Microsoft 365, email link), organisations, projects, elements (floor / panel), the element screen (inputs as JSON, the engine run in the browser, its schedule, save a draft version, approve), the approval route (`app/api/versions/[id]/approve`: role check, server re-run, hash match, service-role write). `proxy.ts` refreshes sessions. Runs without keys in a "not connected" state; `.env.example` lists the settings.
- `supabase/` — `migrations/` (organisations, members with roles, projects, elements, model_versions, approvals, drawings, audit_log; row-level security on all; approved versions frozen; Storage bucket `org-files` with a folder per organisation) and `tests/` (row-level-security tests in PGlite, no Docker). `config.toml` for the Supabase CLI.
- `docs/` — `architecture.md`, `adr/001…008`.
- Tests: `pnpm test` at the top runs every package's tests and type checks through Turborepo (engine `node:test`; prototype `check.js`, `test-grammar.js`, `test-shapes.js`, `test-panel.js`, `test-app.js`; web Vitest; db PGlite). `pnpm build` builds the prototype page and the web app. Browser smoke tests: `node apps/prototype/scripts/smoke.js <dir with node_modules/three>` and `node apps/prototype/scripts/smoke-app.js <same dir>` (install `three@0.128.0` in a scratch dir first; the CDN is not reachable from the test container). **`pnpm test` must pass before every commit; run the smoke tests when viewer code changes.** Use `corepack pnpm` if `pnpm` is not on the path.
- Design docs (claude.ai docs, read them with the Docs tools, not WebFetch): architecture (above); notation reference https://claude.ai/artifact/Di9ePutHNpoTtwQ5ZC3bsX.
- Published prototype (artifact, keep this URL): https://claude.ai/artifact/AyxtiYDBagzRjSgJ3sQgM8 — publish `apps/prototype/dist/index.html` (run `pnpm build` first).
- Deploys: `.github/workflows/pages.yml` (push to `main`: `pnpm test`, `pnpm build`, then the prototype app to GitHub Pages); `.github/workflows/ci.yml` (pull requests and other branches). The web app deploys to Vercel and the migrations to Supabase once Baji has created those projects (open decision in the architecture doc §13).

## Rules for a scheduled run

1. **One backlog item per run.** Take the top unchecked item in `BACKLOG.md`. If it can't be finished in one run, split it into sub-items in place and finish the first.
2. **Don't guess engineering.** Anything that needs an engineer's decision (a detail, a lap value not in a cited table, a convention) goes under "Parked" in the backlog with a one-line question. Use what the drawings/standards say and cite the source in a code comment.
3. **Check before commit.** `pnpm test` must pass (it also parses the built prototype page's whole inline script).
4. **Keep the prototype page self-contained and publishable.** One built `dist/index.html`; external scripts only from cdnjs / jsDelivr / unpkg pinned to exact versions; no downloads or `window.open` (blocked in the artifact viewer); `<title>` stays `X Struc Viewer`. Engine changes go in `packages/engine/src/engine.js` between its MODEL START / MODEL END lines.
5. **Keep the architecture's rules.** Packages never import from apps; only `apps/web` talks to Supabase; every new table has `org_id`, row-level security and a test in `supabase/tests`; schema changes are new migration files, never edits to applied ones.
6. **Commit and push** to `main` with a message like `feat(engine): callout grammar (#2)` referencing the backlog number. Commit messages end with the attribution lines the session is given.
7. **Republish the prototype** to the artifact URL above when its page changed: first read that artifact (a publish to an unread artifact is refused), then publish `apps/prototype/dist/index.html` to it. Never create a second artifact and never delete it.
8. **Write the devlog entry** (`DEVLOG.md`, newest first): date, item done, what changed, check output lines, anything parked, what the next run should take. Tick the item in `BACKLOG.md`.
9. **Stop early rather than push broken work.** If the item can't be made to pass the checks, leave the code uncommitted, write a devlog entry describing the blocker, and end.
10. **Don't change** bar sizes/spacings/laps of the example without a backlog item saying so; don't rename layers A–D; don't reorder the fixing sequence.

## Conventions

- Units: millimetres in the model, metres in the scene (`W(x, y, z)` converts). z = 0 at the main slab soffit; x east, y north.
- Layers: A bottom 1st, B bottom 2nd, C top 3rd, D top 4th (Australian B1/B2/T2/T1). Outer layers A and D run the same way; inner layers B and C run the same way.
- Every bar has `pts` (polyline, mm), `size`, `type` (`N` or `R`), `layer`, `shape`, `run`, `setout`, `note`; `len` and `kg` are derived in `addBar`. Bars with `existing: true` are context only and stay out of the schedule.
- Every run has `label` (short tag text), `callout` (drawing-style wording) and either `dist` (distribution line) or `tagPos` for its tag anchor.
- Keep the UI copy plain and in placing-drawing language (count, size, spacing, layer).
