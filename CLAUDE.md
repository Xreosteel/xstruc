# X Struc — instructions for every working session

X Struc turns engineers' slab and precast drawings into 3D reinforcement models, placing drawings and bar schedules; it is growing from a prototype into a SaaS. Owner: Baji (Xreosteel). Read this file, then `DECISIONS.md` (Baji's decisions; build to them, don't re-ask), then `DEVLOG.md` (latest entry first), then `BACKLOG.md`. The architecture is the **v2 · Lean build** tab of https://claude.ai/artifact/D7Jf59XywqkZmL8UK7xeGm (read it with the Claude Docs tools, not WebFetch); `docs/architecture.md` and `docs/adr/` are the short versions in the repo.

## What exists (a pnpm + Turborepo monorepo since 2026-11-20)

- `packages/engine` — **the engine, the single source of truth**, as TypeScript modules in `src/` (since 2026-11-20, #39): `constants`, `bending` (pins, hooks, cut lengths, shape codes), `laps`, `setout`, `defaults` (`DEFAULT_CFG`), `grammar` (`parseCallout`), `geometry`, `floor` (`buildModel`), `panel` (`buildPanel`, `PANEL_CFG`), `mesh`, `cover`, `inserts`, `sheet`, `sheet-annotate`, `sheet-panel`, `print`, `section`, `pit` (`buildPit`, `PIT_CFG`: a pit / mud trap, strict, #43h; `buildModel` sends `kind: "pit"` to it), `types` (the public interfaces) and `index.ts` (re-exports every module, the typed entry points, `ENGINE_VERSION`, `canonicalOutput`). Modules marked `// @ts-nocheck` are moved code not yet strictly typed; `constants`, `bending`, `setout`, `grammar`, `print` and `pit` are strict. `ENGINE_VERSION` 1.1.0 (pits added). Imports use `.ts` extensions (Node runs the sources directly; `erasableSyntaxOnly`). Pure and headless: no DOM, no THREE, no network, no clock, no randomness (its tests check this). **The golden set** (`test/golden/`: 11 fixtures, full output of every bar, sheet and section pinned by hash) must stay green; a deliberate output change bumps `ENGINE_VERSION` and `package.json` together and re-pins with `pnpm --filter @xstruc/engine golden:update`.
- `apps/prototype` — the single-page viewer and installable app, live until `apps/web` replaces it. `index.html` is a **template**: its `// @@ENGINE …` line is replaced by `scripts/build.js` with the engine bundled by esbuild (an IIFE defining `XStrucEngine`, then one line putting every engine name in the page's scope) → `dist/index.html`, the self-contained page (three.js r128 + OrbitControls from CDN, everything else inline). It renders the example Level 1 floor (layers A–D, beams, columns with starters, set-down, step, balcony, openings, L/Z-bars, extras, stair, mesh), a fixing-order stepper, tags, inspector, live schedule, section cut, placing sheets, site mode, and the precast panel mode (NF / FF faces, bars or mesh). Viewer code lives in `index.html`; engine code only in `packages/engine`. `scripts/test-bundle.js` checks the bundled engine against the golden set.
- `apps/prototype/app` + `scripts/build-app.js` — the installable app (backlog #34) that GitHub Pages serves: https://xreosteel.github.io/xstruc/. Keep the page free of a manifest link (the artifact has no worker); the `appShell` block does nothing without the manifest. The page keeps both modes' inputs in localStorage (`xstruc.inputs.v1`).
- `apps/web` — **the application** (Next.js 16 App Router, React 19, Tailwind 4) for Vercel. **Default: no sign-in** (Baji, 2026-11-20): it opens on the projects kept on the device (`lib/local-jobs.ts`, localStorage `xstruc.web.jobs.v1`; `/job/[id]`, `/job/[id]/[el]`: inputs kept as typed, built on opening, 3D, schedule; Backup / Restore files); the account screens redirect home. With `NEXT_PUBLIC_ACCOUNTS=1` (`lib/mode.ts`) and Supabase keys, accounts are on: Supabase sign-in (Microsoft 365, email link), organisations, the Team page, projects, elements (floor / panel), the element screen (inputs as JSON, the engine run in the browser, its schedule, save a draft version, approve), the approval route (`app/api/versions/[id]/approve`: role check, server re-run, hash match, service-role write). `proxy.ts` refreshes sessions. Runs without keys in a "not connected" state; `.env.example` lists the settings.
- `packages/viewer` — the 3D view of an engine model with three.js 0.187 (#40): `scene-data.ts` (pure: bar segments by layer, concrete prisms, fixing steps, bounds; unit-tested in Node) and `viewer.ts` (`createViewer(container, { onPick })` → `setModel`, `setStep`, `setGhost`, `view('iso'|'plan'|'side')`, `select`, `pickAt`, `screenOf`, `dispose`). Bars are instanced cylinders per layer; concrete is translucent (stair flight and step nib not drawn yet); grid lines with bubbles; on a fixing step the run tags (HTML labels through `CSS2DRenderer`, classes `xs-tag` / `xs-grid`) and distribution lines of that step's layer (`setTags`). `apps/web/components/ModelViewer.tsx` wraps it with the stepper, views, legend and a bar card; `/demo` shows the examples (floor, panel, mud trap) with no account; concrete may be a plan outline pushed up (axis z) or a section pushed across (axis x, the ramp and the walls beside it); the element screen shows it after Build.

## Rules for a scheduled run

1. **One backlog item per run.** Take the top unchecked item in `BACKLOG.md`. If it can't be finished in one run, split it into sub-items in place and finish the first.
2. **Don't guess engineering.** Anything that needs an engineer's decision (a detail, a lap value not in a cited table, a convention) goes under "Parked" in the backlog with a one-line question. Use what the drawings/standards say and cite the source in a code comment.
3. **Check before commit.** `pnpm test` must pass (it also parses the built prototype page's whole inline script).
4. **Keep the prototype page self-contained and publishable.** One built `dist/index.html`; external scripts only from cdnjs / jsDelivr / unpkg pinned to exact versions; no downloads or `window.open` (blocked in the artifact viewer); `<title>` stays `X Struc Viewer`. Engine changes go in `packages/engine/src/*.ts`; when you touch a `@ts-nocheck` module, prefer converting it to strict types in the same change.
5. **Keep the architecture's rules.** Packages never import from apps; only `apps/web` talks to Supabase; every new table has `org_id`, row-level security and a test in `supabase/tests`; schema changes are new migration files, never edits to applied ones.
6. **Commit and push** to `main` with a message like `feat(engine): callout grammar (#2)` referencing the backlog number. Commit messages end with the attribution lines the session is given.
7. **Republish the prototype** to the artifact URL above when its page changed: first read that artifact (a publish to an unread artifact is refused), then publish `apps/prototype/dist/index.html` to it. Never create a second artifact and never delete it.
8. **Write the devlog entry** (`DEVLOG.md`, newest first): date, item done, what changed, check output lines, anything parked, what the next run should take. Tick the item in `BACKLOG.md`.
9. **Stop early rather than push broken work.** If the item can't be made to pass the checks, leave the code uncommitted, write a devlog entry describing the blocker, and end.
10. **Don't change** bar sizes/spacings/laps of the example without a backlog item saying so; don't rename layers A–D; don't reorder the fixing sequence.

## Conventions

- Units: millimetres in the model, metres in the scene (`W(x, y, z)` converts). z = 0 at the main slab soffit; x east, y north.
- Layers: A bottom 1st, B bottom 2nd, C top 3rd, D top 4th (Australian B1/B2/T2/T1). Outer layers A and D run the same way; inner layers B and C run the same way.
- Every bar has `pts` (polyline, mm), `size`, `type` (`N` or `R`), `layer`, `shape`, `run`, `setout`, `note`; `len` and `kg` are derived in `addBar`. Bars with `existing: true` are context only and stay out of the schedule.
- Every run has `label` (short tag text), `callout` (drawing-style wording) and either `dist` (distribution line) or `tagPos` for its tag anchor.
- Keep the UI copy plain and in placing-drawing language (count, size, spacing, layer).
