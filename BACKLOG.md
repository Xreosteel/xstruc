# X Struc backlog

Ordered. Each scheduled run takes the **top unchecked item**, finishes it, ticks it, and logs in `DEVLOG.md`.
An item too big for one run is split into sub-items in place (keep the order). Never skip ahead without a note in the devlog saying why.

Conventions every item must respect are in `CLAUDE.md`.

## Decisions that shape this backlog

See `DECISIONS.md`. The first users are site crews, so items that help a fixer or leading hand build from the model come first.

## Done notes

- #5 (2026-11-11): laps by size and grade. `lapCalc` (between the MODEL markers) gives the AS 3600:2018 Section 13 value for a bar: tension lap 1.25 × Lsy.tb (Cl 13.1.2.2 / 13.2.2: k1 1.3 for a horizontal bar with > 300 of concrete below it, k2, k3 from cd = min(cover to the bar, half the clear spacing), the 29 k1 db floor), compression lap max(Lsy.c, 40db, 300) (Cl 13.1.5.2 / 13.2.4), rounded up to 50, with the governing cd named; coefficients from Findings 2 (secondary sources; verify against the standard). `parseLapTable(text)` reads a B23-style project table (`SLAB 25 32 40` / `N12 600 500 450` … / `BEAM <300`, `BEAM >300`, `BEAM` = both, `COLUMN` with one value per size) with line-numbered errors; `cfg.lapTable` drives the laps where it has a row for the case / size / f'c, the flat `cfg.lap` is the default and fills the gaps (one warning naming them; a missing f'c column is an error). Every run carries `r.lap = { len, src (flat / table / fixed), calc, short, lapped, what }`: the mats (cover to the bar = slab cover for A / D, + the outer bar for B / C), Z-bar and L-bar legs, edge bars, add / extra / trimmer bars, beam bars (narrow-element contact laps, k1 by depth) and the starter projection (950 fixed unless the table has a COLUMN N24 row); `pieces()` and `gridSetout` take the run's lap, the Z-bar / L-bar room checks use the longest mat lap. A lap in use that is shorter than the unrounded formula value is a warning (the example: N16 layer A 600 < 700, EB1 top bars 600 < 800, starters 950 < 960) and shows in the inspector / site card; `M.laps` (source, text, rows) feeds a lap report under the inputs panel with a lap-table textarea. Sheet title and strip carry the layer's lap (`LAP 750 (TABLE)`). The example floor builds bar for bar as before (1,458 / 78 / 5,300 kg).

- #7c (2026-11-10): balconies on any edge, several per floor. `cfg.balconies` is a list of `{name, edge (N/S/E/W), from, to, proj, thk, down}` (`from` / `to` along the edge: mm from grid 1 on N and S, from grid A on E and W); `cfg.balcony` (the #7a north-edge object) is still read as a one-item list. Each balcony carries an edge frame (`along`, `sg`, `a0`, `a1`, `root`, `tip`) and the bar code is written once in that frame, so the example builds bar for bar as before and the other edges are the same bars turned (layers A / D along the edge, B and the cantilever top bars out from it, cogs at the free edges, edge bars on the three free sides, setout from the grid line along the edge). `M.BALCS` replaces `M.BALC`; `M.EXT` (slab + balconies) frames the grid lines, bubbles, dimension strings, chairs, sheet bounds and camera. Rules: ≥ 1,500 along the edge, on the edge, projection 500–4,000, thickness ≥ 2 × cover + 40, set-down 0 to T − 100, not on the step's two edges (N east of the step line, E north of it), 300 between balconies (same edge or meeting at a corner). One balcony with the default name keeps the plain BALC / BALCONY tags; several (or a named one) carry their names. Panel: balcony rows (name, edge select, from / to, out / thk / down), "+ Add balcony" takes the longest free stretch of edge. `check.js`: a four-edge job, the north balcony turned to S / E / W keeps its bars and mass, 6 bad rows by row, step conflicts; `smoke.js`: turn the example's balcony west, add a second (lands on the south edge), clash it, remove it, reset. Cantilevers off the edge-beam sides (S, W) are allowed; question for Baji.

- #7b (2026-11-10): set-downs and the step are inputs. `exampleGeometry(cfg)` adds `setdowns` (WET AREA, 70 deep) and `step` (second-last grid each way, rise 200, nib 300); `buildModel` reads `cfg.setdowns` (`[{name, x0, y0, x1, y1, depth}]`) and `cfg.step` (`{x0, y0, rise, nib}`, slab raised NE of that corner) when given. `M.DROPS` replaces `M.DROP`; one Z-bar run per set-down per layer (`r.drop`), callout names the set-down. Rules: depth 10–160 (Z-bar), rise 161–600 (L-bars on a nib), nib 2 × cover + 100 to 600, set-down ≥ 2 × (lap + half-crank) + 100 each side and lap + half-crank + cover inside the slab edges, clear of beams / the step / other set-downs' Z-bars; step line ≥ max(1,000, lap + 2 × cover + 100) from every edge, nib clear of beams. Panel: Set-downs rows (name + depth, x0 y0 x1 y1) and a Step fieldset; "+ Add" finds a free patch. `check.js`: two-set-down + off-grid-step job, 7 bad rows, 6 bad steps; `smoke.js`: depth, add, break, remove, step edits, reset. Limits are placeholders (question for Baji).

- #7a (2026-11-10): openings and the balcony are inputs. `parseGrids(cfg)` and `exampleGeometry(cfg)` (headless, exported) give the grid-derived Level 1 openings (STAIR VOID, RISER) and balcony (from / to along the north edge, projection 1,800, 180 thick, set down 50); `buildModel` uses `cfg.openings` (array of `{name, x0, y0, x1, y1}`) and `cfg.balcony` (`{x0, x1, proj, thk, down}`) when given, else the example. A bad explicit row is an error naming the row ("Opening 3 (DUCT): sits on beam IB1.", "Balcony: too narrow…") and that row is left out while the rest builds; an example row that does not fit a grid only warns. Checks: numbers, ≥ 300 each side, 300 inside the slab edges, clear of beams / step / set-down, 300 between openings; balcony ≥ 1,500 wide on the north edge, projection 500–4,000, thickness ≥ 2 × cover + 40, set-down 0 to T − 100, clear of the step. Trimmer size follows the opening size (≥ 1,500 → 2-N16 ext 600, else 2-N12 ext 500; question for Baji). The balcony's cog, edge-bar and tag heights and its notes derive from `thk` / `down`; with no set-down the cantilever top bar runs straight (shape L). Panel: openings rows (name + x0 y0 x1 y1, × to remove, + Add opening drops a 600 square mid-slab) and a balcony row inside fieldsets that grey out with their feature toggle; bad rows outlined red. `check.js`: explicit example rows reproduce the example bar for bar; a 3-opening job; 5 bad rows + a bad balcony. `smoke.js`: widen the riser, add, break, remove a row, edit the balcony, reset.

- #9c (2026-11-10): the placing sheet works on site and on paper. Site mode has a **Sheet** chip (44 px) beside 3D / Plan: the stepper's layer as its placing sheet, one finger pans and taps (22 px bar tolerance, tag hit boxes grown to 44 px), two fingers pinch-zoom about their midpoint, the strip keeps to a sixth of the stage. A schedule row (or a mark chip on the site run card) highlights its mark on the sheet: the sheet steps to the mark's layer, every bar of the mark is labelled in the layer colour (`sheetMarksFor`, headless) and the title names it. **Print sheet · A3** (or Ctrl/Cmd+P on the sheet): `beforeprint` lays the sheet alone on A3 landscape with 10 mm margins at the largest standard scale that fits (`sheetPrintScale`, AS 1100.101 / ISO 5455 preferred scales; the example floor prints at 1 : 75), white paper, ~240 dpi, scale and date in the title band; `afterprint` restores the stage. `check.js` asserts highlight labels for every mark and the print scale on A3 / A4; `smoke.js` runs the Sheet chip, a tap and a synthetic pinch at 1024 × 768 and 768 × 1024, the mark highlight, and the print layout including a real PDF capture.

- #9b (2026-11-05): the placing sheet is annotated headlessly. `buildSheet` now returns `tags[]` (one per labelled run of the layer being placed, beside its distribution line or at its tag anchor, slid or pushed to a free place with a leader to its line or bars; never dropped, `overlap` flagged as a last resort), `distLines[]`, `laps[]` (one lap zone per pair of lapped bars, from `b.grid.laps`), `runMarks{}` (every distinct mark of each run labelled, repeats where they fit) and `strip` (floor, layer, f'c, cover, laps, bar / mark count, mass and the layer's callouts). Sheet text is paper text sized in mm (tags 220, marks 150, notes 170), so the declutter holds at any zoom; feature notes are obstacles. The canvas draws them; clicking a tag selects the run (its marks appear beside its bars), the selected bar's lap zones are labelled, and the fit leaves room for the title band and the strip. `check.js` asserts tags / leaders / distribution lines / lap zones / marks / strip on every sheet and a crowded sheet where every D tag starts at one point; `smoke.js` clicks the main tag and zooms in.

- #9a (2026-11-04): `buildSheet(M, solid, ghost)` between the MODEL markers returns a layer's placing drawing as plan geometry: `bars[]` (plan polyline, `cogs[]` ticks with a unit normal and the leg height, `kind: "cog" | "vertical"` for a starter seen end-on, `ghost`), `chairs[]`, `grids` with bubble positions, `gridDims[]`, `dims[]` (setout from the nearest grid to each run's first and last bar line, on the run's distribution line, from `r.grid`), `concrete` outlines, `notes[]` and `title[]`. - #21 (2026-11-04): a mat callout without E-W / N-S is an error in the inputs panel, never a guessed default. `matDirectionError(direction)` (between the MODEL markers) accepts only X / Y; silence, "each way" (two layers in one line) and wall/beam words (horizontal, vertical, longitudinal, transverse) each get their own wording. - #20 (2026-11-04): grid setout lives in the model. `nearestGrid`, `barAxis` and `gridSetout` sit between the MODEL markers; every bar with a plan axis carries `b.grid = {dir, ends, line, from, to, laps[], lineIndex, n, sp}` and every run of parallel lines (mats, balcony) carries `r.grid = {first, last}`. Each ref is `{v, grid, at, d, side, text}` from the nearest grid line; a lap zone's two ends are measured from the same grid. The desktop inspector shows bar line (with "line i of n @ sp"), both ends and lap zones; the site card reads the same object; fitments show their position along the beam. `check.js` asserts the refs add up, use the nearest grid, match the geometry and lap flags and cover every bar line; `smoke.js` asserts the inspector and site-card wording.
